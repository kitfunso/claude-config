Clef decision models: where we use them

KITFUNSO, 3 October 2026. Status tags: live building now next later

The idea. A decision model answers typed questions about any text (and, for the 27B Clef, images): yes/no with a probability, pick one of up to 255 options, or a 2 to 10 level score. It does not write text. Clef-flash answers in about 40 ms at the vendor, about 300 ms from here, and Cloudflare gives 10,000 free neurons a day (about 970 small calls). Run locally on the RTX 5080 it is free and unlimited, and no data leaves the PC.

Where it wins. Four places: (1) an LLM call that only picks, grades or routes; (2) a regex that stands in for meaning; (3) a human look that only says yes or no; (4) a judgement nobody makes today because an LLM call per item was too slow or too dear. Place 4 is the big one: at 40 ms and no cost we can judge every tool call, every reply, every memory and every log line.

Where it loses. Writing text, counting, dates, arithmetic, and anything a lookup gets right. It never abstains, so every choice needs a no-match option and every noul needs its own threshold from a bench.

5. Rules every use follows

  • Labelled cases first, two free baselines, threshold declared in EXPERIMENT-PROTOCOL.md before the run (the /jev skill loop).
  • Fail open: no key, an error or a spent allocation means the old behaviour.
  • Hosted calls leave the machine: scrub secrets in code; private data (2chain, work) goes to the local server only.
  • Never the paid tier: free allocation or local only.
  • A model probability is not a fact. Hippo keeps its observed / inferred / verified status apart from any Clef score.
