Where the tokens go

Last 14 days of transcripts on the home box, measured 8 Oct 2026. 60,494 API calls across 173 main sessions and 995 sub-agents. A second pass the same day corrected two of the first pass's recommendations; section 5 says which.

Two thirds of the burn is sub-agents. The largest single block is Opus agents doing build work: a quarter of all burn went to Opus agents whose brief was a code build with a test check, and the spawn call named Opus every time. The main thread is a third. Reply length and the config files are small by comparison.

4. Main thread

Under a third of the burn. The big sessions hold a mean context of 137k to 154k for 800 to 2,300 calls each. Tool mix: Bash 44.8%, Edit 16.2%, Read 13.5%, Grep 10.0%. Shell reads still happen: 2,152 sed -n calls and about 565 cat calls across all threads.

Config text is 18,128 tokens a prompt today, against 16,375 on 13 Sep. It is a small part of a 145k context.

5. What changed on 8 Oct

  1. An Opus agent no longer gets a code build without a reason.largest
    New Sub-agents rule in the global CLAUDE.md: a code build from a complete brief runs on Sonnet. A new hook, the spawn guard, moves an Agent call that names opus to Sonnet and tells the caller, when the brief names tests and a worktree, branch or commit. A line Opus because: <what is still open> in the brief keeps Opus. The first version denied the call; a deny shows a hook error and costs a second send of the brief, so it became a rewrite the same evening. Reviews, debugging, planning, design, research, drafting and skill-run orchestrators pass untouched. Backtest on these 14 days: 122 of 1,038 spawns caught, 24.6% of all burn, with no review and no Sonnet spawn among them. Sonnet weighs half of Opus, so the ceiling is about 12% of all burn.
  2. Five agent types lost the Skill and PowerShell tools.small, about 2%
    typescript-pro, python-backend-engineer, frontend-developer, debugger and senior-code-reviewer now carry disallowedTools: Skill, PowerShell. In 14 days those types made no Skill call and 39 PowerShell calls between them, against 8,818 Bash calls. Measured before and after with the same one-word brief: starting context fell from 35.0k to 37.0k down to 21.4k to 23.4k, 13.6k off every call each of them makes. The 2% is an estimate from shares.
  3. Every sub-agent starts with a three-line contract.unmeasured
    Batch independent reads and read line ranges; do not wait on CI or a remote job; stop when the brief's check passes and return what is done, what remains and the next step. It aims at the 11.0% in chained single reads and the 7.2% in idle rewrites. It is a notice, so the week-on measure decides whether it works.
  4. Briefs.part of item 1's rule
    The same CLAUDE.md bullet asks for one slice per agent ending in a commit, file:line pointers, a return at push, and worker or a specialist type over general-purpose, which starts 14k to 18k tokens heavier.

Checks that closed the work: 28 unit tests on the hook pass, and the whole hooks test folder passes (209 Python, 80 Node). Live, in fresh claude -p sessions: a sub-agent quoted rule 2 of the contract back; an Opus build spawn ran on Sonnet only and the caller quoted the guard's notice; the same spawn with an Opus because: reason, on its own line or in mid-sentence, ran on Opus. Nothing is committed in ~/.claude.

5a. Measured and left alone

  • The compaction window stays at 250k. The first pass suggested a 150k trial. That was wrong: the simulation puts a 150k window at +4.7% of all burn on the main thread, because compactions cost more than the smaller context saves. Change in all burn by window, main then sub-agents: 220k −1.0 and −3.0; 200k −1.3 and −4.1; 180k −0.8 and −4.8; 160k +1.6 and −4.5; 150k +4.7 and −3.3. A 200k window models at −5.4% in total with two thirds more main-thread compactions (271 to 453). The model leaves out what a compaction loses, so the setting is unchanged. It is the next thing to trial.
  • No call cap on sub-agents. The first pass called this the largest lever because agents over 100 calls hold 39% of all burn. Holding the burn is not the same as wasting it. Cutting an agent into slices is close to compacting it earlier, which the simulation puts at 3 to 5% of all burn at best, and a cut in the middle of a task costs a handoff. The one-slice rule sits in the brief rule and the contract; no hook counts calls.
  • The agent files keep model: opus. The default decided 0.2% of burn.
  • Critics stay on Opus: your call. Opus critics are 13.8% of all burn. devrl's own A/B found no measured premium for Opus critics (mean reward 23.06 against 22.63), and the 23 Sep routing rule then moved every review to Opus. Sonnet critics would save about 7% of all burn.
  • One review per PR: not done. devrl runs a critic at every stage by design. Cutting the critic set is a redesign of the skill, not a setting.
  • No CLAUDE.md for mechanical agents: not done. omitClaudeMd takes 10.7k off every call, and takes the git, secrets and sourcing rules with it.
  • Parallel hippo agents and /clear: habits, nothing to configure.

5b. The first pass's list, kept for the record

Written before the second pass. Item 1's size and item 7's window were wrong, item 2 named the right target but not the cause, and item 6 is now tested (section 3c).

  1. Cap sub-agent length.largest
    Agents over 100 calls are about 39% of all burn. Brief each agent for one slice that ends in a commit, around 60 to 80 calls, and have the next slice start in a fresh agent from the commit plus a short handoff note. A fresh agent restarts at 45k where the old one sat at 135k.
  2. Route executors to Sonnet when the plan is already written.large
    Opus general-purpose and typescript-pro executors dominate. The routing rule already says Sonnet for mechanical work at half the per-token price; an executor following a reviewed plan mostly is mechanical. Keep Opus for the planner and one reviewer.
  3. One review per PR.medium
    251 senior-code-reviewer spawns are about 10.6% of all burn. Review the final diff once; skip per-stage reviews on small changes.
  4. Hand agents file:line pointers and ranged reads.medium
    The main thread usually knows where the code is. Put src/x.ts:120-180 in the brief and tell the agent to Grep first and Read with offset and limit. Whole-file reads are close to a third of everything agents take in.
  5. Keep agent tool calls under five minutes.medium, 6.3%
    Run the targeted test file, not the full suite, inside an agent. A call that outlasts the 5-minute cache makes the next call rewrite the full context at the write price.
  6. Give executors a narrow tool list.medium, untested
    The 19k gap between worker (25k start) and all-tools agents (44k start) rides in every call. I have not tested whether the gap is tool schemas or config text. One spawn of each with the same brief would settle it.
  7. Main thread: /clear between unrelated tasks; try a 150k compaction window.small to medium
    Sessions sit near 145k for thousands of calls. A lower window trades more compactions for a smaller context on each call. Worth a one-week trial, measured with the same script.
  8. Fewer hippo agents in parallel on the heavy days.scheduling
    Three days took 78% of the fortnight. The work was real; the plan limit is hit by how many long agents run at once.

Not worth chasing: reply length, the CLAUDE.md and MEMORY.md text (18k of a 145k context), Fable (2.3%).

7. Limits of the measurement

  • "Burn" is weighted tokens: cache read 0.1, 5-minute write 1.25, 1-hour write 2, output 5, times a model weight (Fable 1, Opus 0.4, Sonnet 0.2, from the price ratios in the global CLAUDE.md). The plan limit may weigh these differently. The raw token counts in section 2 do not depend on the weights.
  • Calls are deduped by request id. Two scripts split main and sub-agent slightly differently (66.2% by file location, 69.9% when side-chain records inside main files are counted).
  • Transcripts show activity on 24 to 29 Sep, 3 to 4 Oct and 8 Oct only. Nothing is recorded for 30 Sep to 2 Oct or 5 to 7 Oct.
  • The spawn guard's 24.6% is a backtest of what it would have moved to Sonnet in these 14 days. The saving is at most half of that, since Sonnet weighs half of Opus, and less for every brief that keeps Opus with a reason.
  • Not measured: whether a Sonnet builder needs more fix rounds than an Opus one. If it does, the saving shrinks. Burn per merged PR a week on is the check.
  • The compaction simulation replays the measured context growth with a different trigger. It reproduces the measured main-thread cache reads to 100% and the sub-agent ones to 105%, and it does not model the detail a compaction loses.
