PROJECT forecast: the pipeline, stage by stage

Written DATE under ~/.claude/skills/quant-ml-protocol/SKILL.md (revised 2026-09-29). Each row names the check that closes the stage; the full check text is the numbered stage in SKILL.md and is not repeated here. A stage is done when its check has run, its pass condition holds and its page exists. A true blocker (known leakage, preprocessing fitted on future rows, unmatured labels in training, judge reuse, a broken target, invalid chronology, a null that does not replay the search) blocks every later stage; a caution flag (no vintages, unknown revision risk, small sample, late start, coarse null, seed variance, unstable regimes) is listed here and the campaign continues; a negative research result is a pass. A blocker verified after a result was read invalidates that result whatever its sign: the result is kept and marked invalid, the fix gets a regression test, a rerun on inspected judge data is a diagnostic correction only, and the corrected spec confirms on fresh matured outcomes as a labelled challenger. A coverage failure (a primary driver neither held nor obtained, a coverage row open or blocked for a refused reason) stops the stage 4 or stage 8 freeze it guards. Nothing downstream starts on a partial stage unless the gap is written here first.

Open choices, answered by the data at stage 7

Nothing below is fixed. Sibling-project results (bd, wb, td3c) are cells to include, not priors.

The grid: window {expanding; rolling LADDER} x refit {DECLARED LADDER; annual, quarterly, monthly, weekly by default for daily data} x recency weight {none; half-life LADDER}, recency weighting a candidate family and not an assumption, = N cells per family and horizon. Row floor: R training rows; rungs below it are not fittable and say so. Feature windows: z-score {LADDER}, change {LADDER}, lag {LADDER}. Common forecast-date set per horizon: FROM to TO. Families, every rung run (F1 to F6 in the coverage table): champion alone; regularised linear; shallow trees; equal-weight average; stacking; sequence models, as labelled exploratory context where the sample cannot support them; each from F2 up on the shortlist and on the whole tier 1 set held to the cap, both declared before stage 5. Mechanism rungs M1 to M10 beside them. Tuned family, at least one: FAMILY. Tuning: Optuna = 200 trials exactly whenever a study runs; search space SPACE; seed SEED; objective OBJECTIVE; inner purged walk-forward DEFINE; pruning DEFINE; tuned ONCE PER FAMILY AND WINDOW / PER GRID CELL; retuning RETUNE AT EVERY REFIT / AT EACH COARSEST-CADENCE REFIT (default) / ON A DECLARED SCHEDULE / ONCE ON A DEVELOPMENT PERIOD, SCORED AFTER IT, each study completed on data before the forecasts it serves; the null replay reruns every 200-trial study on that schedule, cost STUDIES x B x 200 trials. Deterministic grids: SIZE. Compute: one full replay benchmarked at T minutes per family; thinning for FAMILY declared here: STATE IT.

Selection rule, written before the run: highest nomination oriented primary skill against the champion on the primary horizon H, with the orientation declared in references/targets-and-metrics.md; raw metrics reported beside it. Tie rule: a cell is in the tie set when the paired block-bootstrap interval of its oriented primary skill minus the best cell's, on identical forecast dates, contains zero (overlap of two separate intervals is not the test); the tie-break is DECLARED COMPLEXITY SCORE (refits, recency weighting, window length, compute; frozen before the grid) / the least-machinery order fewest refits, no recency weight, longest window (leans to expanding; a stability prior, not a statistical rule), and it picks one cell per family; the tie set is reported as a set and as a fraction of the grid. A winner that exists only in the latest year is a regime split, not the live spec's selector.
