PROJECT forecast: the pipeline, stage by stage

Written DATE under ~/.claude/skills/quant-ml-protocol/SKILL.md (revised 2026-09-22). Each row names the check that closes the stage; the full check text is the numbered stage in SKILL.md and is not repeated here. A stage is done when its check has run, its pass condition holds and its page exists. A true blocker (known leakage, preprocessing fitted on future rows, unmatured labels in training, judge reuse, a broken target, invalid chronology, a null that does not replay the search) blocks every later stage; a caution flag (no vintages, unknown revision risk, small sample, late start, coarse null, seed variance, unstable regimes) is listed here and the campaign continues; a negative research result is a pass. Nothing downstream starts on a partial stage unless the gap is written here first.

The grid: window {expanding; rolling LADDER} x refit {DECLARED LADDER; annual, quarterly, monthly, weekly by default for daily data} x recency weight {none; half-life LADDER}, recency weighting a candidate family and not an assumption, = N cells per family and horizon. Row floor: R training rows; rungs below it are not fittable and say so. Feature windows: z-score {LADDER}, change {LADDER}, lag {LADDER}. Common forecast-date set per horizon: FROM to TO. Families: champion alone; regularised linear; shallow trees; equal-weight average; OTHERS with the rule that admits them. Tuning: Optuna = 200 trials exactly whenever Optuna is used; search space SPACE; seed SEED; objective OBJECTIVE; inner purged walk-forward DEFINE; pruning DEFINE; tuned ONCE PER FAMILY AND WINDOW / PER GRID CELL; the null replay reruns the full 200-trial study. Deterministic grids: SIZE. Compute: one full replay benchmarked at T minutes per family; thinning for FAMILY declared here: STATE IT.

Selection rule, written before the run: highest nomination oriented primary skill on the primary horizon H, using the comparator and orientation declared in references/targets-and-metrics.md; raw metrics reported beside it. Tie rule: a cell is in the tie set when the paired block-bootstrap interval of its oriented primary skill minus the best cell's, on identical forecast dates, contains zero (overlap of two separate intervals is not the test); the tie-break is DECLARED COMPLEXITY SCORE (refits, recency weighting, window length, compute; frozen before the grid) / the least-machinery order fewest refits, no recency weight, longest window (leans to expanding; a stability prior, not a statistical rule), and it picks one cell per family; the tie set is reported as a set and as a fraction of the grid. A winner that exists only in the latest year is a regime split, not the live spec's selector.
